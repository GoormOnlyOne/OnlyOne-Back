█ 근본 원인 및 해결

  원인: WHERE m.message_id IN (SELECT MAX(...) ...) 구문에서
        MySQL 옵티마이저가 서브쿼리 결과를 materialized temp table로
        만든 뒤 외부 message 테이블을 풀 스캔 (type=ALL, 3.1M rows)

  해결: derived table JOIN 방식으로 변경
        FROM (SELECT MAX(m2.message_id) AS max_id ... GROUP BY ...) sub
        JOIN message m ON m.message_id = sub.max_id
        → 외부 message 접근이 type=eq_ref (PK lookup, 결과 수만큼만)

  EXPLAIN 비교:
  - Before: m type=ALL, rows=3,157,362
  - After:  m type=eq_ref, rows=1 (per sub row)
